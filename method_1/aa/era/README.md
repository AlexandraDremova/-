# Классификатор эпохи (aa/era)

Многоклассовый CAMeLBERT-CA, который по сегменту из 8 бейтов определяет **эпоху** стихотворения.
Обучается на [arbml/APCD](https://huggingface.co/datasets/arbml/APCD): 1.83 млн бейтов, 12 эпох.

Для проекта у классификатора две задачи:

1. **Сам по себе.** Насколько хорошо по стилю различаются эпохи арабской поэзии. Оценка ведётся по поэтам с p-value и сравнением с базовыми линиями.
2. **Для муаллак.** Насколько муаллака «доисламская» по сравнению с поэмами дивана её же поэта. Если муаллака или её часть (например, вступление Антары) поздняя или сильно переработана, она должна выглядеть *менее* доисламской, чем его диван. Это независимый от A8 признак: модель ничего не знает о наших 10 поэтах.

## Порядок запуска

```bash
pip install datasets            # только для загрузки APCD с HuggingFace
# (если HF недоступен: huggingface-cli download arbml/APCD --repo-type dataset --local-dir data/raw/apcd
#  и дальше --apcd data/raw/apcd)

# 0. датасет проекта, как обычно (нужен, чтобы вычистить из APCD бейты муаллак и диванов)
python -m aa.data.build_dataset --out data/processed/dataset.parquet

# 1. APCD -> сегменты с эпохами (~5–15 мин, в основном чистка и поиск вариантов бейтов)
python -m aa.era.apcd --apcd arbml/APCD --project-data data/processed/dataset.parquet \
    --out data/processed/era_dataset.parquet

# 2. дымовой прогон: 1 фолд, 1 эпоха, маленькая выборка — несколько минут; проверка, что GPU и обучение живы
python -m aa.era.run_era_cv --folds 1 --epochs 1 --max-seg-per-class 300 --eval-seg-per-class 300 --no-baselines

# 3. полная CV по поэтам (5 фолдов) + базовые линии
python -m aa.era.run_era_cv --scheme coarse            # --resume, если прервалось

# 4. муаллаки: 3 seed, BERT + n-граммы, эталон из диванов
python -m aa.era.run_era_cases --scheme coarse --seeds 3
```

Результаты пишутся в `data/processed/era_<схема>/`, логи — в `logs/era_*.log`. Прогресс и оставшееся время выводятся каждые 100 шагов и после каждой эпохи и фолда.

**Время на RTX 4060 — грубая прикидка, не замер.** При ограничениях по умолчанию (≤ 6000 сегментов на класс) эпоха обучения идёт порядка 2–4 минут. Значит, фолд занимает ~10–15 минут, полная CV — около часа, `run_era_cases` с 3 seed — 30–45 минут. Точное время покажет дымовой прогон.

## Схемы классов (`--scheme`)

| Схема | Классы | Что выбрасывается |
|---|---|---|
| `binary` | доисламская / исламская классическая | мухадрамы (переходные), новое время |
| `coarse` (по умолчанию) | доисламская / ранний ислам + Омейяды (+ мухадрамы) / Аббасиды (+ «между державами») / поздняя классика (Андалусия, Фатимиды, Айюбиды, Мамлюки, Османы) / новое время | ничего |
| `full` | все 12 эпох APCD | классы, где меньше 8 поэтов |

Сопоставление эпох APCD с классами задано в `labels.py` (`SCHEMES`) и меняется там. Арабские названия эпох сопоставляются по нормализованным подстрокам. Нераспознанные значения не теряются молча: `aa.era.apcd` печатает их вместе со счётом. **Перед первым прогоном проверьте в логе `apcd`, что все 12 эпох распознаны.**

Почему по умолчанию `coarse`: в `full` соседние эпохи различаются в основном датой, а не языком. Андалусия к тому же выделена по географии и пересекается по времени с Аббасидами и Айюбидами. Для вопроса о муаллаках прямее всего `binary`, его стоит прогнать вторым.

## Как устроена защита от утечек

| Риск | Что сделано |
|---|---|
| Модель учит поэта, а не эпоху | CV по поэтам: поэт целиком в одном фолде. Валидация для ранней остановки и калибровки — тоже отдельные поэты |
| Плодовитые поэты и большие эпохи перетягивают | ≤ 40 сегментов на поэта и ≤ 6000 на класс, набор «по кругу» по поэтам; взвешенный loss |
| Наши 10 поэтов в обучении | исключены по имени (`labels.PROJECT_POETS_*`). Похожие имена (например, «أعشى همدان» — другой поэт) не исключаются, а печатаются для ручной проверки. `--exclude-poets` добавляет имена |
| Муаллаки и диваны в APCD под чужими именами | бейты проекта выбрасываются из APCD: точные совпадения во всех эпохах, варианты (Жаккар триграмм ≥ 0.5, как в `aa.data.dupes`) в ранних эпохах |
| Один бейт у разных поэтов APCD | выбрасывается везде: атрибуция спорная, а при разбиении по поэтам это утечка между обучением и тестом |
| Границ поэм в APCD нет | псевдо-поэма — подряд идущие бейты с одним поэтом, диваном, размером и рифмой |

## Что считается

**`run_era_cv`** — классификатор как таковой. Файлы `era_cv_*.csv`:

- **Метрики.** Балансная точность (главная: классы несбалансированы), macro-F1, точность, «точно или соседняя эпоха», AUC для P(доисламская). Всё считается на уровне сегментов и поэтов (у поэта — средняя лог-вероятность его сегментов).
- **95% интервал** — стратифицированный кластерный бутстреп по поэтам. Единица независимости — поэт, а не сегмент.
- **p против случайного** — перестановка эпох между поэтами при фиксированных предсказаниях.
- **BERT против базовых линий** на тех же сегментах. Линии: символьные n-граммы 2–4 + логистическая регрессия, «только метр», самый частый класс. Считаются бутстреп разности по поэтам, перестановочный тест (ответы двух методов меняются местами по поэтам) и поправка Холма. «Только метр» показывает, сколько эпохи угадывается по одной форме.
- **Куда уходят исходные эпохи** (`era_cv_by_original_era.csv`). Например, к какому классу модель относит мухадрамов.

**`run_era_cases`** — муаллаки:

- P(доисламская) муаллаки = среднее по её сегментам.
- **Эталон** — «одна невиденная поэма из k сегментов» того же поэта из его дивана aldiwan. Это тот же байесовский эталон, что в A8 (`aa/eval/reference.py`). Диваны очищаются тем же `aa.data.prepare`: без копий муаллак и вариантов их бейтов.
- **p** = доля эталона ≤ P муаллаки. Объединение по seed — правило Рюгера, поправка Холма — по муаллакам, отдельно для BERT и для n-грамм.
- **Калибровка температурой** по валидационным поэтам APCD, только смягчение (T ≥ 1). Дообученный BERT переуверен. Без калибровки P(доисламская) у большинства сегментов дивана уходит за 0.99, а эталон на логит-шкале обрезает значения до [0.01, 0.99] и вырождается. Предсказанный класс калибровка не меняет. Если сегментов за границей всё равно больше половины, в логе будет предупреждение. `--no-calibrate` отключает калибровку.
- `era_cases_segments.csv` — P по каждому сегменту муаллаки (среднее, мин и макс по seed). Здесь видно, совпадает ли место провала с CAMeLBERT-атрибуцией: у Антары это сегменты 1–5.
- `era_diwan_summary.csv` — средняя P(доисламская) и доля сегментов, отнесённых к доисламской эпохе, по дивану каждого поэта. Это проверка переноса модели на тексты aldiwan: ни один из 10 поэтов в обучении не участвовал.

## Как читать результат и чего он не доказывает

- **Низкая P у муаллаки — это «звучит позднее», а не «подделка».** Возможные причины: тема и жанр (насиб, винная тема обычнее в поздней поэзии), правка передатчиков, поздние вставки, огласовка и орфография конкретного издания.
- **Ранние классы APCD разнородны.** Метка эпохи стоит на поэте, а не на стихотворении. У мухадрамов и у поэтов «между державами» часть стихов из одной эпохи, часть из другой.
- **Источник текста.** APCD, по-видимому, собран в том числе с aldiwan, как и наши диваны (поля и названия диванов совпадают): перенос на «другое издание» это не проверяет (см. п. 4 плана — OpenITI).
- **Поэты с малым диваном** (Харис, Амр): эталон не строится (< 5 поэм или почти нет поэм из ≥ 2 сегментов), вывод — «нет эталона».

## Файлы модуля

| Файл | Что внутри |
|---|---|
| `labels.py` | эпохи, схемы, нормализация арабского, список поэтов проекта |
| `apcd.py` | сборка датасета эпох (CLI) |
| `split.py` | метки схемы, фолды по поэтам, ограничение выборки, веса классов |
| `model.py` | `EraClassifier` (обучение, ранняя остановка, bf16 с откатом в fp32, сохранение) |
| `metrics.py` | метрики, бутстреп и перестановки по поэтам, парное сравнение, калибровка температурой |
| `baselines.py` | n-граммы, «только метр», самый частый класс |
| `run_era_cv.py`, `run_era_cases.py` | прогоны (CLI) |

Тесты — `tests/test_era.py`. Они идут без сети и без torch: на синтетическом APCD, с заглушкой вместо BERT.
