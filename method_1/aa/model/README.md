# `aa/model/` — модель и инференс (дорожка сокомандника)

Ансамбль попарных CAMeLBERT-классификаторов + majority vote, с оценкой уверенности.
Реализует контракт `interface.py`, поэтому подставляется в `aa/eval/harness.py` без правок.

## Файлы
| Файл | Что делает | Зависит от torch |
|------|------------|:---:|
| `interface.py` | контракт: `fit` / `train_pair` / `predict`, валидатор ответа | нет |
| `sampling.py` | отбор ~60 примеров на поэта; перечисление пар авторов | нет |
| `voting.py` | majority vote + определение `confidence` | нет |
| `finetune.py` | `PairClassifier` + `train_pair` — дообучение бинарного CAMeLBERT | **да** (ленивый импорт) |
| `ensemble.py` | `fit` (все пары) + `predict` (голосование) | да (ленивый) |
| `run_cv.py` | прогон ансамбля через eval-харнесс на parquet | да |
| `stub.py` | заглушка для дорожки данных (не трогать) | нет |

## Определения, зафиксированные с дорожкой данных
- **Вход `predict`** — уже очищенный текст (диакритика/кашида сняты на стороне данных); модель только токенизирует.
- **label 1 = target, 0 = opponent** в каждой паре.
- **confidence** = средняя вероятность, которую присвоили победителю все модели с его участием (∈[0,1]). На этом строится калибровка порога — определение не менять молча.

## Запуск — порядок важен (финальный прогон)
```bash
export HF_HUB_OFFLINE=1      # CAMeLBERT уже скачан: без сетевых проверок HuggingFace
# 1) дубли и варианты бейтов муалак в диванах (секунды)
python -m aa.data.dupes --data data/processed/dataset.parquet
# 2) кросс-валидация: метрики + ЭТАЛОН для муалак (~35 мин)
python -m aa.model.run_cv --data data/processed/dataset.parquet --n-splits 3 --epochs 30 --early-stop-loss 0.01
# 3) A8: 10 муалак, 3 независимых ансамбля (seed), сравнение с эталоном (~30 мин)
python -m aa.model.run_cases --data data/processed/dataset.parquet --seeds 3 --epochs 30 --early-stop-loss 0.01
# 4) только пересчитать p-value по готовым файлам шагов 2–3, без обучения (~1 мин)
python -m aa.model.rescore_cases
```
Шаги 2 и 3 используют одну и ту же подготовку данных (`aa/data/prepare.py`): без муалак,
без их точных копий в диванах и без сегментов с вариантами их бейтов (Жаккар триграмм ≥ 0.5).
В кросс-валидации поэмы с общими/похожими бейтами всегда попадают в один фолд.

**Потоковый режим (по умолчанию в run_cv/run_cases).** Пара обучается → сразу считает
нужные тексты → выгружается. Модели на диск НЕ сохраняются (одна пара ≈ 440 МБ, 45 пар ≈ 20 ГБ),
в памяти одна модель за раз. Сохраняющий режим (`ensemble.fit` + `predict_many`) остаётся
для случая, когда обученные модели нужно переиспользовать.

**Воспроизводимость.** Seed фиксируется в начале обучения каждой пары (`config.SEED`):
голова классификатора и порядок батчей одинаковы от запуска к запуску.

**bf16.** На GPU с поддержкой bf16 (RTX 30xx/40xx) обучение и инференс идут в смешанной
точности — быстрее и меньше памяти. Отключить: `--no-amp`.

## Параметры (`aa/config.py`)
`CHECKPOINT` (CA по умолчанию; для экспа — `...camelbert-mix`), `EXAMPLES_PER_POET=60`,
`EPOCHS=100`, `LEARNING_RATE=2e-5`, `BATCH_SIZE=16`, `MAX_OPPONENTS` (None = все пары).

## На ревью (что проверить)
- Логика `sampling`/`voting`/`predict`/потокового ансамбля покрыта `tests/test_model_logic.py`
  и проходит **без torch**.
- Реальное обучение проверено на одной паре (imru-alqays vs labid, RTX 4060): train_acc → 1.0
  к 10–15 эпохе, test acc 0.83 (20 эпох) / 0.87 (100 эпох) на 23 тестовых сегментах.
- Открытый вопрос к обсуждению: определение `confidence` (сейчас — средняя вероятность
  победителя). Если захотим ближе к статье — можно взять долю голосов или мин. вероятность.

## Логирование и скорость
- Все скрипты (`run_cv`, `run_cases`, `diagnose_pair.py`) пишут лог в консоль **и** в `logs/<скрипт>_<время>.log`.
  Следить за долгим прогоном из второго терминала: `tail -f logs/run_cv_*.log`.
- В логе: устройство (GPU/CPU — предупреждение, если CPU), длины сегментов в токенах, по эпохам
  `loss` и `train_acc` с оценкой оставшегося времени, прогресс по парам ансамбля и фолдам.
- Паддинг динамический (до самого длинного в батче), а не до 512 — в разы быстрее.
- `--early-stop-loss 0.01` — остановить пару, когда train-loss < 0.01 три эпохи подряд.
  По умолчанию выключено (честные 100 эпох как в статье).

## Устойчивость обучения (по итогам прогона A8 от 26.10)
В первом прогоне 3 из 45 пар ушли в NaN при обучении в bf16 (al-asha/amr, amr/labid, labid/tarafa).
Сломанная модель давала NaN-вероятности, а голосование молча отдавало её голос второму автору
пары — таблица муалак оказалась испорчена. Сейчас:
- при первом NaN/inf в bf16 пара **переобучается с нуля в fp32** (в логе — WARNING, в сводке пар `fallback_fp32=True`);
- клиппинг нормы градиента (`MAX_GRAD_NORM=1.0`);
- инференс всегда в fp32 и падает с понятной ошибкой, если вероятность не число;
- голосование отвергает NaN вместо тихого голоса за второго автора;
- **взвешенный loss для несбалансированных пар** (`BALANCE_PAIRS`): у Хариса 14 обучающих сегментов,
  у Амра 26, у Тарафы 47 против 60 у остальных — без весов модель смещается к более крупному автору.

Выходные файлы `run_cases`: `mualaqat_cases.csv` (таблица), `mualaqat_cases_segments.csv`
(раскладка по сегментам: голоса и топ-3 авторов), `mualaqat_cases_pairs.csv` (сводка обучения пар).
`run_cv` дополнительно пишет `cv_pairs.csv`.

## Как читать результат A8 (`mualaqat_cases.csv`, после пересчёта — `mualaqat_cases_v2.csv`)
- `увер_в_приписанном` — средняя по сегментам муаллаки уверенность ансамбля в приписываемом поэте
  (среднее по seed; `увер_мин`/`увер_макс` — разброс между seed).
- `p` — главный показатель: насколько вероятно, что настоящая поэма этого поэта той же длины получила бы
  такую же или более низкую уверенность. Эталон — «одна невиденная поэма из k сегментов»
  (`aa/eval/reference.py`, `single_poem_reference`): модель «эффект поэмы + разброс сегментов внутри поэмы»
  на логит-шкале, байесовский предсказательный эталон по невиденным в CV поэмам того же автора.
  p трёх seed объединены правилом Рюгера (1.5 × медиана, корректно при любой зависимости между seed);
  `p_seed_мин`/`p_seed_макс` — разброс.
- `p_Холм` — p с поправкой Холма на число оцениваемых муалак (`проверок_в_поправке`, без Хариса и Амра).
- `вывод`: `p_Холм ≤ 0.05` — аномально низкая похожесть на автора; `p ≤ 0.05` без поправки — ниже типичной;
  `p ≤ 0.20` — слабый сигнал; иначе — в пределах нормы; у автора < 30 обучающих сегментов — нельзя оценить.
- `ожидаемая_увер` — медиана эталона, `граница_5%` — уверенность, ниже которой p < 0.05 (без поправки).
- `ICC_автора` — насколько сегменты одной поэмы похожи друг на друга (0 — не похожи, 1 — одинаковы).
  Чем выше ICC, тем шире эталон для длинной поэмы.
- `перцентиль_старый` — прежний эталон (смесь коротких поэм), только для сравнения: он был слишком узким.
- `устойчивость` — одинакова ли категория p (≤ 0.05 / ≤ 0.20 / > 0.20) во всех seed.
- `recall_CV`, `попарная_точность` — насколько модель вообще узнаёт этого автора.
- `ближайший_по_голосам` — справочно. Голосование систематически перекошено к Зухайру,
  ан-Набиге и Абиду (см. матрицу ошибок CV), поэтому имя «ближайшего» — не вывод об авторе.
- Шкалы сопоставимы: каждый ансамбль A8 учится на 2/3 диванов (по поэмам, по каждому автору),
  ровно как модели эталона в 3-фолдовой CV.
- Задача закрытая: модель выбирает одного из 10 поэтов, даже если автор — кто-то другой.

### Почему эталон заменён (28.10)
Старый эталон собирал «поэму из k сегментов» из нескольких коротких поэм автора (у Антары поэма в среднем
меньше двух сегментов). Сегменты одной поэмы похожи друг на друга, поэтому среднее по одной настоящей поэме
разбросано сильнее, чем среднее по смеси. На синтетике с известным ответом старый эталон бракует настоящую
длинную поэму в 9–19% случаев вместо 5%, новый — в 2–8% (чаще всего 4–6%). Подробно — `refcheck/README.md`.

### Проверка эталона на настоящих поэмах
`rescore_cases` по очереди считает каждую поэму дивана «спорной», строит эталон по остальным поэмам того же
автора и записывает её p (`mualaqat_cases_v2_calibration.csv`). Сводка — `mualaqat_cases_v2_calibration_summary.csv`:
доля p ≤ 0.05 у честного эталона ≈ 5%, p ≤ 0.20 ≈ 20%. Небольшое превышение ожидаемо, если в диванах
есть поэмы с ошибочной атрибуцией. `mualaqat_cases_v2_reference_fit.csv` — оценки модели по авторам и проверка допущения
«уверенность не зависит от длины поэмы» (`связь_длины_и_уверенности`).

Устойчивость: `--scale prob` (модель без логита), `--method bootstrap` (запасной способ эталона); для них задавай свой `--out`, чтобы не перезаписать основной результат.

## Отступления от статьи (сказать ментору)
| Что | В статье | У нас | Почему |
|---|---|---|---|
| learning rate | «Adam по умолчанию» (1e-3) | 2e-5 | 1e-3 обычно разваливает дообучение BERT |
| эпохи | 100 | ≤30 + ранняя остановка (loss<0.01 ×3) | 20 vs 100 эпох: 0.83 vs 0.87 на одной паре, ×5 по времени |
| баланс пар | 60/60 | 60 и меньше у малых диванов + взвешенный loss | у Хариса 14 сегментов, у Амра 26 |
| выборка 60 сегментов | не описано | своя для каждой пары | иначе пары крупного поэта видят одни и те же 60 |
| уверенность (confidence) | не описано | средняя вероятность автора по его парам | см. voting.py |
| порог «сомнительно» | не описано | p-value против эталона «одна невиденная поэма автора той же длины», поправка Холма | см. aa/eval/reference.py |
| метрика 0.97–1.0 | по контексту — «поэт против оппонента» | считаем и попарную точность, и 10-классовый F1 | 10-классовая задача строже |
| точность вычислений | — | bf16 при обучении, откат в fp32 при NaN | ×3 быстрее |
| проверка спорных поэм | одна модель, уверенность 0.71 vs 0.99 | 3 ансамбля на 2/3 данных, p-value против эталона «одна поэма той же длины», правило Рюгера по seed, Холм по муаллакам | абсолютный порог не сопоставим между авторами и длинами |
| утечки | не описано | убраны копии муалак, варианты их бейтов; CV по группам поэм с общими бейтами | иначе модель видит тестовый текст |
