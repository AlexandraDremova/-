# План работ — дорожка «Модель и инференс»

> Документ для сокомандника и его AI-агента. Самодостаточный: агент может брать задачи отсюда.
> Проект: атрибуция авторства доисламских арабских поэтов. Воспроизводим метод из статьи
> *BERT-based Classical Arabic Poetry Authorship Attribution* (COLING 2025, Alqurashi et al.).
> Второй участник (Элина) ведёт дорожку **«Данные и оценка»**.

---

## Контекст в двух абзацах

Задача — по тексту стихотворения оценивать, кому из поэтов он принадлежит, и с какой уверенностью (confidence нужен для детекции неверной атрибуции — это цель всего проекта).

Метод из статьи: **НЕ один многоклассовый классификатор**, а ансамбль маленьких бинарных моделей. Для целевого поэта обучается серия моделей «целевой автор против одного другого автора» (оптимум по статье: 1 оппонент, ~60 примеров на поэта), каждая — дообученный CAMeLBERT. Итог — majority vote по ансамблю. В статье ансамбль дал F1 ≈ 0.98 против 0.75 у одиночной модели. Предобученный CAMeLBERT берём готовый: **`CAMeL-Lab/bert-base-arabic-camelbert-ca`** (классический арабский), заново не предобучаем.

**Почему метод такой:** доисламских данных мало, поэтому задачу декомпозируют в много простых попарных различений стиля. Следствие для нас: обучать на всём корпусе из 784 поэтов не нужно — только целевые поэты + пул контрастных.

---

## Твоя роль: Модель и инференс

Ты владеешь каталогом **`model/`**. Отдаёшь наружу обучение и предсказание; остальное (данные, eval, калибровка) — на стороне напарника. Между вами два контракта, зафиксированных на совместной сессии (см. ниже). Пока датасет напарника не готов — работаешь на стаб-данных из «скелета».

---

## Фаза 0. Совместная сессия (90–120 мин) — делаем вместе

Из неё надо выйти с рабочим «скелетом» в общем репозитории и двумя контрактами. Твои зоны ответственности на сессии:

1. **Окружение (~15 мин).** Поднять `requirements.txt` (`transformers`, `torch`, `camel-tools`, `pandas`, `scikit-learn`, `datasets`). Запустить фоновую загрузку `CAMeL-Lab/bert-base-arabic-camelbert-ca`, пока обсуждаете остальное.
2. **Контракт данных (~30 мин)** — согласовать с напарником. Ты это *получаешь*, но участвуешь в решении про единицу сегментации (чтобы примеры влезали в 512 токенов) и препроцессинг. Схема одной строки:
   ```
   {poem_id, author, period, century, topic (пока null), text}
   ```
   Формат: parquet или jsonl, строка = один сегмент стихотворения.
3. **Контракт модели (~20 мин)** — это твоя граница. Зафиксировать сигнатуры, чтобы eval напарника мог звать модель вслепую:
   ```python
   train_pair(target: str, opponent: str, df) -> model_path       # одна пара, ~60 примеров/поэта
   predict(text: str, ensemble) -> {"pred_author": str, "confidence": float}
   # ensemble = список попарных моделей + majority vote
   ```
4. **«Идущий скелет» (~30–40 мин).** Вместе собрать игрушку: 2 поэта × несколько сегментов → обучить одну пару → получить одно предсказание с confidence. Точность не важна — важно, что труба работает end-to-end.
5. **Фиксация (~10 мин).** Коммит скелета, распределение владения файлами, договор о точках синхронизации. Оба стартуете с одного коммита.

## Фаза 1. Самостоятельная работа — твои задачи

Работаешь против стаб-датасета из скелета, пока не придёт Sync 1.

- [ ] **`model/finetune.py` — обёртка дообучения.** Загрузка `bert-base-arabic-camelbert-ca` + голова бинарной классификации. Adam (дефолтный lr), ~100 эпох как стартовая точка из статьи (потом подрежешь по кривой обучения). Токенизатор того же чекпоинта, `max_length=512`.
- [ ] **`train_pair(target, opponent, df)`** — обучение одной пары: берёт из `df` примеры двух авторов (~60 на каждого), обучает, сохраняет модель, возвращает путь.
- [ ] **One-vs-one цикл.** Для целевого поэта строишь несколько моделей против разных оппонентов. Параметры из статьи как дефолт: 1 оппонент, 60 примеров/поэта — вынеси в конфиг, их потом будут перебирать.
- [ ] **Ансамбль + majority vote.** Сборка списка попарных моделей; агрегация голосов в финальный класс.
- [ ] **`predict(text, ensemble)`** — возвращает `pred_author` **и** `confidence`. Confidence критичен: именно по нему детектится подделка (в статье спорная поэма получила 0.71 против обычных 0.99). Продумай, как считаешь confidence из голосов/вероятностей — согласуй определение с напарником, он на нём строит калибровку порога.
- [ ] **5-fold кросс-валидация** внутри обучающего цикла.
- [ ] Короткий `README` в `model/`: как вызвать обучение и предсказание.

**Указания для агента (важные детали, легко упустить):**
- Вариант CAMeLBERT в статье явно не назван. Дефолт — **CA**; заложи возможность переключить чекпоинт на `...camelbert-mix` как отдельный эксперимент.
- Препроцессинг текста (снятие диакритики и кашиды через CAMeL Tools) делает **сторона данных** — модель получает уже чистый текст. Не дублируй чистку в `model/`, только токенизация.
- Муалаки длинные → сегментация обязательна, иначе обрезка по 512 токенов потеряет текст. Но сегментация — не твоя зона, ты принимаешь готовые сегменты.
- Не хардкодь имена авторов/пути — всё через конфиг, потому что набор поэтов будет меняться.

## Точки синхронизации (с твоей стороны)

| Sync | Ты получаешь | Ты отдаёшь |
|------|--------------|------------|
| **1 — датасет-срез** | Маленький, но настоящий датасет (3–4 поэта полностью обработаны), parquet/jsonl | Подтверждаешь, что обучение идёт на реальных данных; меняешь стаб |
| **2 — рабочий predict** | — | Модуль `model/` + сохранённая модель: обучение пары + `predict()` с confidence на реальных данных |
| **3 — интеграция** | Полный датасет + eval-харнесс | Полный ансамбль; вместе получаете первые честные F1 и прогоняете 10 муалак как кейсы |
| **4 — финал** | Калиброванный порог уверенности от напарника | Финальный инференс под процедуру вероятностной оценки (ТЗ) |

Между Sync 2 и 3 вы разблокированы: напарник гоняет eval против твоего `predict`, ты крутишь параметры ансамбля.

## Чего пока НЕ делаешь

- **ETM (тематический контроль)** — фаза 2, улучшает результат, но для первой рабочей итерации не нужен. Берёт его тот, кто раньше освободится (логичнее — сторона данных, это корпусный препроцессинг; репозиторий `ssharoff/ETM`).
- Сбор контрастного пула пост-исламских поэтов, калибровку порога и проверку изданий (OpenITI) ведёт напарник — ты только предоставляешь `predict()`, на котором это работает.
